## 莫尔斯二叉树解码器 — 固件烧录说明

芯片：CH32V003F4P6（TSSOP-20，16K Flash / 2K RAM，HSI 24MHz，无需晶振）

### 交付文件

- `Morse_CH32V003_NORMAL.hex` / `.bin` — 正式固件（日常使用，开机侧音音量 50%）
- `Morse_CH32V003_VOL0.hex` / `.bin` — 正式固件，开机静音（0%）
- `Morse_CH32V003_VOL20.hex` / `.bin` — 正式固件，开机低音量（20%）
- `Morse_CH32V003_BRINGUP.hex` / `.bin` — 板卡自检固件（首次焊好后建议先烧这个验证硬件，UART 会打印自检日志）

NORMAL / VOL0 / VOL20 三版源码完全相同，区别仅在 `CFG_VOLUME_DEFAULT_PCT`
（侧音开机默认音量）；BRINGUP 与 NORMAL 的区别是 `APP_BUILD_MODE` 宏。

### 资源占用（NORMAL）

| 项目 | 占用 | 上限 |
|---|---|---|
| Flash | 7224 字节（代码 7176 + 初始化数据 48） | 16384 |
| RAM（静态） | 476 字节（data 48 + bss 428） | 2048 |
| 栈 | 256 字节（栈顶 0x20000800） | — |

### 烧录方法（任选其一）

方法 A — WCH-LinkUtility（推荐，最简单）

1. 硬件：WCH-LinkE 的 SWD 三线（SWCLK / SWDIO / GND）接芯片对应引脚，另外给芯片供 3.3V（也可用 LinkE 的 3.3V 输出）。CH32V003 的 SWD 引脚是 PD1（SWCLK）和 PD2（SWDIO）。
2. 打开 WCH-LinkUtility，点 "Search" 或手动选择 "WCH-LinkE"，连接成功后选芯片型号 CH32V003。
3. 切到 "Program" 页，选择 `.hex` 文件（Intel Hex 格式自带地址信息，直接选 NORMAL 版即可），点 "Program"。
4. 烧完后点 "Reset" 或直接断电重启，固件即开始运行。

方法 B — MounRiver Studio 2（已安装）

1. 打开 MounRiver，File → Open 或直接新建工程均可；最省事的做法是用自带下载工具：菜单 Window → Show View → WCH-Link 面板，连接 LinkE 后选择 hex 文件下载。
2. 也可以把 `firmware\Morse_CH32V003` 目录作为 Makefile/脚本工程导入后用 build.bat 重新编译。

方法 C — 命令行（wchisp / OpenOCD）

```
wchisp flash Morse_CH32V003_NORMAL.bin
```
（wchisp 为第三方 CLI 工具，需另装；.bin 烧到地址 0x00000000）

### 上电验证清单

1. 上电后所有 LED 应熄灭，蜂鸣器无声。
2. UART（PD5=TX，115200 8N1）在 BRINGUP 固件下会打印自检信息；NORMAL 固件下按键解码时会打印节点号/字符。
3. 短按电键发 "SOS"：···  ---  ···，对应 LED 应沿二叉树路径逐层点亮。
4. 按住 CLEAR ≥1 秒清除所有 LED。
5. 旋转电位器（PC4）调节速度，T 应在 60~300ms 范围内变化（约每 100ms 采样一次）。

### 串口调音量（NORMAL 固件）

在 115200 8N1 串口终端敲命令并回车：

- `V30` → 音量设为 30%，返回 `VOL=30%`
- `V0`  → 静音
- `V?`  → 查询当前音量
- `?`   → 列出命令

音量本质是侧音 PWM 占空比（0~100），上电默认 50（可在源码
`app_config.h` 的 `CFG_VOLUME_DEFAULT_PCT` 改）。电位器仍专职调速，不冲突。

### 已验证事项

- morse_core 纯 C 核心：PC 端 10 组单元测试全部通过（含 BUG-1 回归测试）。
- SysTick 配置已对照 EVT 官方 Systick 例程核对（WCH 自定义外设，直接写寄存器）。
- ADC 为 10 位（满量程 1023），PC4 = ADC 通道 2，采样 241 周期，含校准。
- 蜂鸣器 PD0 = TIM1_CH1N，已按 EVT ComplementaryOutput 例程配置 BDTR。
- 硬件文档 V1.4 §8.2 的 NODE_TO_LED 勘误已在代码中修正。
